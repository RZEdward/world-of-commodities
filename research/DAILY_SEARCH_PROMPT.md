# Daily and on-demand search instructions

Prompt version: 2026-11-07.3

Use this as the operating prompt for a World of Commodities research run. **Fast Coverage is the default**: maximize the number of relevant roles Ross sees quickly. Use Complete Search only when Ross explicitly asks for an exhaustive baseline or audit. Read the live workbook and linked methodology first. The workbook controls names, IDs, owners, rankings and geographic scope; this file controls search behavior. Do not substitute a copied list for the current registry. The reusable Codex workflow is `.cursor/skills/opportunity-scout/SKILL.md`.

> ### A1. Fast Coverage default and Complete Search gate
>
> **Fast Coverage** is the normal weekly search. Complete a broad title-led discovery pass in every active Job Search city, including employers absent from Company Registry. Search **every active ranked company** as a targeted second layer on each requested Fast Coverage run. Use Company Rankings only to order and batch work; no rank or tier is a reason to omit an employer. Check each employer's global vacancy inventory once and reconcile vacancies to registered cities; never multiply checks by office-city pairs. Prioritize HK/SG leads first, then location rank and company rank. Check deadlines within 7 and 30 days and high-value or changed tracked roles. Do not manually reread every unchanged role, research reviews, or assess desk outlook. Use leads with visible confidence states; do not delay plausible vacancies while seeking perfect fields. Save one compact `employer-outcomes.json` row per ranked company with its ID/rank, checked source, outcome (relevant vacancy found, no relevant vacancy found, source unavailable, or manual fallback required), and relevant requisition URLs. A run is complete for Fast Coverage when all active Job Search cities have a recorded query-pack outcome, all active ranked employers have an outcome row, all discovered candidate leads have been triaged/deduplicated, urgent deadlines and status signals have been checked, and deferred work is stated. Do not claim every tracked role was individually reverified.
>
> **Complete Search** is only for an explicit request for a full search, baseline, initial complete set, or audit. Complete Fast Coverage first so the lead list is available early. Then inspect each active ranked employer’s global careers/ATS inventory once, reconcile each vacancy to only its named registered cities, and refresh every active role row that falls in the requested scope. Do not interpret 982 company-city mappings as 982 separate vacancy searches. Office address verification, review research, recruiter mapping, market-data discovery and university discovery are separate batches; include them only if the requested complete scope calls for them. University programme search iterates the University Registry, not every city alone.
>
> Do not close a requested Complete Search while a required batch is `Not started`; save a checkpoint and mark the run `Incomplete — resume required` if work is interrupted. For Fast Coverage, an inaccessible employer source must be logged explicitly and routed to fallback where practical; it is not silently skipped. The closeout must state actual elapsed time and completed/deferred coverage. The ledger should reconcile: registered Job Search cities queried / total; ranked employer inventories with outcomes / total; leads found and triaged; new/changed roles verified; deadlines within 7/30 days checked; and tracked role rows refreshed versus deferred. Keep office-city pair counts as registry diagnostics, not vacancy-search completion criteria. Count a real vacancy once per distinct requisition and registered city.

> ### B. Fast Coverage workflow
>
> 1. Run a compact city/title query pack in every Job Search city. Group searches regionally where useful, but keep city-level coverage outcomes. Search title families and synonyms; include employers outside Company Registry. Search older listings too if they still appear open.
> 2. Search Hong Kong and Singapore first, then remaining cities by owner location rank and company priority. In China/Japan/Korea, include English plus Simplified Chinese/Japanese/Korean query packs.
> 3. Check every active ranked employer inventory as a targeted second layer. Use one global career/ATS inventory check per employer, not one search per mapped office. Batch companies in rank order for efficiency; record an explicit outcome for every ranked employer in `employer-outcomes.json`. Broad city searches remain the safety net for employers that have not yet been added to the registry.
> 4. A specific vacancy from a credible LinkedIn, recruiter, aggregator, or employer source can be entered as a visible Jobs row before employer-site confirmation. Set `Confidence` to a clear `Lead — [source type; verification state]`, preserve the URL in `Link`, date in `Date Found`, and short verification task in `Next Action`. Use Research Inbox for vague hiring claims or employer-identity ambiguity, not to hide a real vacancy lead from the Opportunities view.
> 5. Check existing roles with deadlines within 7 days, then 30 days, as well as status-change signals, recently changed pages, and user-managed application activity. Preserve prior status for roles not rechecked; do not imply they were freshly verified. Do not expire a role solely because its link fails or disappears from search results.
> 6. Keep notes short and deduplicate by requisition ID, canonical URL, employer/title/city. Do not research long compensation breakdowns, company histories, reviews, or desk outlook in Fast Coverage.
> 7. Keep office mapping, recruiter/network discovery, company-universe evidence from market data, and Glassdoor/Reddit research outside Fast Coverage. Run them on their separate cadence or when requested. These are slower, optional research families and should not hold up role discovery.
> 8. Divide Fast Coverage into disjoint regional batches when parallel researchers are available. Return concise role leads and city/query coverage, not essays. The coordinator deduplicates, assigns confidence, updates the workbook, and refreshes the dashboard. Never take control of the user's desktop when another project may be using it; public web research can proceed without a signed-in browser.

> ### C. Keep company scope selective

## Search cadence and learning rule

These are starting cadences; Search Coverage Log records evidence for adjusting them:

- **Daily when requested:** Fast Coverage of new roles/changes, Hong Kong and Singapore first; no full employer audit, reviews, or desk-outlook research.
- **Weekly:** Fast Coverage across all Job Search cities and every active ranked employer inventory; deadline checks within 7/30 days. Office address, recruiter, market-data, and speculative-route audits are separate families, not automatic job-sweep requirements.
- **Monthly/admissions-cycle:** programme discovery/refresh for active University Registry entries and urgent deadlines; periodically updated official market data.
- **Quarterly or when new evidence appears:** Glassdoor/Reddit reputation research. Research desk outlook only when it may change a high-value role assessment or Ross requests it.
- **Event-driven:** new auction/market notices, regulator releases, official company expansion or desk news, and a posting or status signal.

Do not downgrade a useful search family after one quiet run. Consider reducing frequency only after at least three comparable, logged runs show low yield, and retain a periodic check or event trigger. Increase frequency after meaningful yield, a change in source publication schedule, or a user request. Keep a separate on-demand full pass available.

## Search Coverage Log fields

Each row represents a repeatable source-family and market/query batch. Use the same family and scope labels between runs so yield is comparable. Efficient query packs may combine cities or source platforms, but record actual coverage; do not mark an unsearched city or family as checked.

`Run ID`; `Checked On`; `Search Family`; `Source / Platform`; `Market / Location Scope`; `Company Category / Rank Band`; `Query Pack / Search Terms`; `Language`; `Cadence Used`; `Items Reviewed`; `Relevant Leads`; `New Roles`; `Updated Records`; `Registry Candidates`; `Duplicates`; `Rejected`; `Elapsed Minutes`; `Yield / Evidence Notes`; `Cadence Recommendation`; `Next Review On`; `Source URLs`.

Run-level elapsed time and usage visibility live in Search Runs. Search Coverage Log records enough detail to decide whether a source family should be daily, weekly, monthly, event-driven, or paused. Keep the search query/result batch aggregated; do not turn the log into a copy of every result.

## Learning loop and prompt maintenance

At the close of every run, review Search Runs and Search Coverage Log against actual source yield, time cost, duplicate rate, and the reason useful leads were found or missed. Feed repeatable lessons into the next run: improve query wording and native-language synonyms, reorder sources, add a reliable source family, clarify evidence checks, or adjust cadence. Update this prompt and any affected playbook/script when the change is reusable; put the date, version, reason, and affected section in the change log below. Keep the owner-approved scope, scoring weights, inclusion threshold, and application-status rules intact unless Ross changes them. A single quiet run is not enough to reduce coverage: use the existing three-comparable-runs rule. Leave unsearched batches explicitly marked as gaps; never imply complete coverage. At each run's closeout, refresh the dashboard feed and static build, and record whether that succeeded.
